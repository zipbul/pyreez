# pyreez 채점 재설계: 호스트 순위 채점 (host-ranking)

상태: **설계 확정 (구현 단계 로드맵 포함)**
검증: v6·v7 두 차례 3자 적대 리뷰(codex + 독립 검증자 + 코드 대조)를 거쳐 도달한 코어.

## 1. 목표

도메인/주제별로 각 모델의 강점을 익명·공정하게 여러 런에 걸쳐 학습하고, 미래 런에서 주제에 맞는 팀을 자동 구성한다. pyreez는 정답 키(ground truth) 시스템이 아니다 — 결과물의 **가치**를 상대적으로 평가한다.

## 2. 코어 설계 (검증 통과)

**호스트가 같은 런에서 나온 익명 답들을 "순위"로 채점한다. 절대점수(1~100)를 매기지 않는다.**

- pyreez가 워커를 실행하고, 호스트에게는 익명 답(라벨 A·B·C…, 순서 셔플)만 전달한다.
- 호스트는 가치 기준으로 **순위**만 제출한다 (예: `B > A > C`).
- pyreez는 라벨↔실제 모델 매핑을 알고 있어, 순위를 `(주제, 축)` 셀의 **상대 비교 관측**으로 기록한다.
- 여러 런이 쌓이면 주제별 모델 강약이 드러나고, 자동 팀 선택에 쓴다.

### 왜 순위인가 (절대점수 대비 이점 — 검증됨)
- **호스트 스케일 교락 소거**: 순위는 호스트가 후하든 짜든 무관(순서만 봄).
- **태스크 난이도 교락 소거**: 같은 런의 답은 같은 문제를 받으므로 난이도가 상쇄된다.
- 절대점수는 이 둘이 모델 실력과 교락되어 `.pyreez/ratings.json` 셀을 오염시킨다.

## 3. 실제 동작 시나리오

1. 호스트가 던진다: *"당뇨 진단법 설계"*
2. pyreez가 워커 3개를 돌려 익명 답 **A·B·C**를 호스트에 전달(누가 어느 모델인지 호스트는 모름).
3. 호스트가 순위 제출: *"B > A > C"*.
4. pyreez는 내부적으로 안다 — B=grok, A=opus, C=haiku. → `medicine/diagnosis` 주제에 **grok > opus > haiku** 관측 1건 기록.
5. 이런 런이 수십 건 쌓이면 *"의료 진단은 grok이 강하다"* 가 통계적으로 드러난다.
6. 다음 의료 태스크에서 자동 팀이 grok을 우선 배치한다.

## 4. 단계적 로드맵 (측정 우선 — 전면 전환 금지)

전면 BT 전환을 한 번에 하지 않는다. 적대 리뷰가 확인한 스케일 비호환·식별 문제 때문에, 인프라를 먼저 깔고 데이터를 모아 **순위가 절대점수보다 실제로 나은지 측정한 뒤** 전환한다.

### Phase 1 — 인프라 (저위험, 적대 리뷰 승인)
- **A1. Run manifest 영속화**: deliberate 완료 시 원자적 저장 — `runId`, protocol, topic, axis schema version, `{ (runId, round, workerIndex) → (실제모델, 답 digest) }`, 표시 순서, `pending/submitted` 상태. debug capture와 독립(`--no-debug-capture`여도 저장).
  - 주의: 동일 모델이 여러 슬롯에 들어갈 수 있으므로(`wire.ts` round-robin) 라벨 키는 **모델이 아니라 `(round, workerIndex)`** 여야 한다(`cli-anonymize.ts`의 모델-키 라벨러는 중복 모델을 한 라벨로 붕괴시킨다).
- **A2. `rank-submit` CLI**: `rank-submit --run <id> --axis <a> --ranking "B>A>C"`. `(run, axis)` 유니크 + idempotency key로 중복/부분/상충 제출 거부. 한 ranking = 1 원자 레코드.
- **F. 주입 방어**: 답 본문을 구조화 전달 + robust delimiter 인코딩 + untrusted-content 명시(`</answer>` 삽입만으로는 의미 수준 주입을 못 막음).

### Phase 2 — 순위 신호 수집 (기존 학습 불변)
- 순위를 **별도 append-only 로그**에 기록. 기존 절대점수 파이프라인은 그대로 병행(폴백 보장, 관측 0 방지).
- 순위 → **런/호스트 단위로 군집된** pairwise 관측(완전순위 1개를 N개 독립 관측으로 세지 않음).

### Phase 3 — 측정 게이트 (정량 기준)
전환 전, 오프라인에서 아래를 측정하고 **사전 고정한 기준**을 통과해야만 다음 단계로 간다:
- `(protocol, 상위 domain)`별 비교 그래프 giant component 비율
- bridge edge 최소 관측 run 수
- 모델별 distinct host 수, host-model 이분 그래프 연결성
- θ separation/발산 발생률 상한
- 절대점수 대비 held-out pairwise log loss (BT가 실제로 더 나은가 = 결정 품질 A/B)

### Phase 4 — 조건부 전환 (셀별 shadow/champion)
- 전역 스위치 금지. 충분한 pairwise + multi-host coverage가 있는 `(domain, protocol)` 셀만 BT 사용, 나머지는 절대점수 유지.
- θ posterior는 절대점수 셀과 **물리적으로 분리 저장**(스케일 비호환: θ는 로그오즈, 셀은 1~100). `select.ts`에 명시 모드 분기.
- 계층 BT: 리프가 아니라 상위 도메인 계층에서 적합 + 리프는 shrinkage. θ→Gaussian(Laplace 근사) 후 기존 thompson 샘플러 재사용, 공동 posterior 1회 샘플링.

## 5. 적대 리뷰에서 **반려·제외**된 것 (재litigate 금지)

| 항목 | 반려 사유 |
|------|-----------|
| 다중 호스트로 문체편향 "완전 제거" | host 가산 offset은 런 내 순위 차분에서 상쇄(σ((θ_A+h)−(θ_B+h))=σ(θ_A−θ_B)) → **비식별**. host×model 교차노출 강제 스케줄러 없이는 불가. |
| 탐색 슬롯 강제(C1/C2 하드쿼터) | 소팀(N=2,3)에서 품질 슬롯을 0~1개로 잠식. Thompson이 이미 적응적 탐색+taper 수행 → 강제는 **퇴행**. 탐색은 prior-variance로 Thompson에 위임. |
| 절대점수→BT 즉시 전면 전환 | θ(로그오즈)를 [1,100] 셀에 직접 못 씀(`store.ts` 가드), 스케일 비호환. Phase 4 셀별 전환으로만. |
| 호스트 절대점수 채점(1~5) | 저장소 1~100과 척도 불일치 → 최고점이 최악 관측으로 강등. 순위로 대체. |

## 6. 정직한 한계

- **완전 공정은 불가**: 답 본문 문체로 모델 계열이 드러나 호스트가 자기 계열을 은근히 선호하는 편향은 완전히 제거되지 않는다. "더 공정"이지 "완전 공정"이 아니다.
- **적재적소는 현재 Thompson이 이미 수행 중**: 본 설계는 채점 신호의 공정성을 개선할 뿐, 탐색 로직을 새로 강제하지 않는다.
- host×model 교차노출이 부족한 배포(단일 호스트)에서는 문체편향 보정이 원리적으로 불가하다.

## 7. 근거

- LLM-as-judge self-preference: 자기 출력 인식(self-recognition) + low-perplexity 선호에서 유래, 이름 익명화로 제거 안 됨 (arXiv:2410.21819, arXiv:2404.13076).
- 절대점수 vs 순위: 순위가 스케일 드리프트에 강건, 집계 순위는 정확도와 높은 상관 (arXiv:2504.14716).
- Bradley-Terry / 계층 pooling: 희소 셀 대응 (JMLR 24, arXiv:1712.05879).
