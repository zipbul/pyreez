# 설계 v4: 주제별 모델 강점 점수 시스템 (확정안)

상태: DRAFT (pyreez 최종 검토 대기)
날짜: 2026-07-15
선행: v1·v2(3자 적대 리뷰 기각) → v3(pyreez 심의 기각) → 실측 5회 → v4

## 0. 실측 체인 — 이 설계의 모든 결정은 측정에서 나왔다

| # | 측정 | 결과 → 설계 결정 |
|---|------|------------------|
| 1 | 6도메인 × 3모델, 단일 judge | opus 전승 — 그러나 judge가 anthropic이었음 → 재측정 필요 |
| 2 | 같은 응답을 3사 judge 교차 채점 | **judge마다 승자 뒤집힘** (grok judge가 grok에 99점, 타 judge 84) → **다중 judge 중앙값 필수, 단일 고정 judge 금지** |
| 3 | medicine 하위주제 3개, 다중 judge | **같은 도메인 안에서 하위주제별 승자 뒤집힘** (진단: gpt / 약리: opus) → **도메인만으론 부족, 하위주제 세분화 필요** |
| 4 | 같은 문제를 형식 변형(JSON·축약·장문맥) | 형식이 순위를 뒤집음 → **형식은 강점이 아니라 교란. 채점에서 형식 배제** (사용자 지적으로 교정) |
| 5 | 형식 통제 + 내용 축만(accuracy·depth·grounding) + 다중 judge 중앙값, 5주제 | **순수 내용만으로 주제별 순위 갈림 확정**: medicine은 grok>gpt>opus(opus 꼴찌), 나머지 4주제 opus 1위. 내용 축이 신호 증폭(혼합 축 1~3점차 → 내용 축 최대 15점차). medicine 역전은 측정 3과 독립 재현 |

## 1. 확정 설계

### 채점 — 순수 내용 가치만
- **축**: `accuracy`(사실 정확성) · `depth`(추론 깊이) · `grounding`(근거 타당성). 단순 토큰(파싱 안전).
  명료성·형식·길이·문체는 **채점 금지** — 실측 4가 형식을 교란으로 확정, 실측 5가 내용 축의
  변별력(최대 15점차)을 확정.
- **judge**: 채점 대상 모델과 **다른 provider의 judge들**로 채점, **중앙값** 채택.
  (실측 2: 단일 judge는 self-preference로 순위를 뒤집는다. 모델 단위 judge 배정이므로
  3사 팀이어도 각 모델마다 타사 judge 2명 확보 — v3의 "팀 단위 중립 judge 0명" 검열 해소.)

### 업데이트 — 매 실행, R1만
- **매 pyreez 실행마다** 갱신 (사용자 요구: 가끔이 아니라 매번).
- 채점 대상은 **R1(첫 라운드) 출력만**: R1은 각 모델이 피어를 보기 전 혼자 낸 답
  (engine.ts:418,445 확인) → 팀 오염 없는 격리 신호. R2+는 상호 참조로 오염되므로 채점 제외.
  R1은 어차피 실행되므로 **워커 추가 비용 0** (judge 콜만 추가).
- R1이 격리인 병렬 프로토콜(shared_convergence·adversarial_debate)이 기본 채점 대상.
  특화 프로토콜의 R1도 격리면 포함(구현 시 프로토콜별 R1 격리 여부 확인).

### 분류 — 주제 계층 + 적응적 깊이
- 계층: `도메인/하위주제/키워드` (예: `medicine/diagnosis/pulmonary-embolism`).
  실측 3이 하위주제 필요를 확정. 키워드 계층은 저장만 하고, **선택에 쓰는 깊이는 데이터
  밀도가 결정**(적응적 깊이): 리프부터 올라가며 신뢰 임계(judge 중앙값 n ≥ 임계) 충족하는
  가장 깊은 계층 사용, 얇으면 부모로.
- 주제 배정: 호스트 `--topic` 우선, 없으면 judge 콜에 분류 얹기(상위 도메인은 고정
  taxonomy 택1로 드리프트 제한, 하위는 자유 라벨).
- 백오프는 점수 대체가 아니라 **prior**: 리프 = 부모 사후를 prior로 한 베이지안 갱신.
  단 v3 리뷰 지적(반상관 형제가 섞인 부모는 역부호 prior 가능)은 잔존 위험 — 리프 n이
  쌓이면 prior에서 벗어나는 구조로 완화, 한계로 명시.

### 저장
- `.pyreez/ratings.json`: `(model, topic-path, axis) → (mean, n, M2)` Welford.
- 사후분산 = `1/(n/σ² + 1/prior_var)` (정규-정규 켤레 — v2의 수식 오류 교정본).
- 메타: 실행별 protocol·팀구성·judge 목록을 raw 로그로 보존(사후 재분석용, v3 리뷰 반영).
- 기존 affinity(축적 0건) 삭제·대체. `pyreez ratings` 커맨드로 사람이 열람.

### 선택 — 옵트인 자동 팀
- `--auto-team N`: 쿼리 주제경로 추정 → 해당 셀(적응적 깊이)에서 모델별 사후
  `Normal(mean, post_var)` 톰슨 샘플 → 상위 N. 제약: provider ≥ 2, 모델 중복 금지.
- 기본은 `--models` 수동 유지. 콜드스타트 탐색 비용은 옵트인으로 사용자가 선택.

## 2. v1~v3 리뷰 지적의 처리 현황

| 지적 (리뷰어) | v4 처리 |
|---|---|
| 단일 judge 편향 (전원) | 다중 judge 중앙값 + 타사 judge (실측 2 근거) |
| 팀-조건부 오염·비전이 (전원) | R1(격리) 채점으로 원천 차단 |
| 3-provider judge 검열 (v3 전원 critical) | 모델 단위 judge 배정으로 해소 (팀 단위 아님) |
| 프로토콜 3종 채점 제외 자기모순 (v3) | R1 격리 채점은 프로토콜 무관 → 제외 불필요 |
| 톰슨 분산 수식 오류 (v2) | 켤레 공식으로 교정 |
| axes 공급원 부재 (v2 codex) | 기본 축 3개 하드코딩 |
| z-정규화 n=2 붕괴 (v2) | 정규화 폐기, 원점수 저장 |
| 형식 교란 (사용자) | 내용 축만 채점, 형식 채점 금지 |
| 키 비대칭(사전추정≠사후라벨) | 잔존 — raw 로그 보존으로 진단 가능, 완전 보정은 범위 밖(한계 명시) |
| 백오프 역부호 prior (v3) | 잔존 위험 — 리프 우세 구조로 완화(한계 명시) |
| judge 공통편향(verbosity 등) (토론) | 내용 축 + "형식 무시" rubric로 완화, 완전 제거 불가(한계 명시) |

## 3. 정직한 한계
1. R1 채점도 "그 프롬프트·그 렌즈에서의 R1"이지 순수 능력의 완전한 분리는 아니다.
2. judge 3사의 공통 편향(전 judge가 공유하는 선호)은 중앙값으로 안 걸러진다.
3. 하위주제 신호는 주제·문제에 따라 강도가 다르다(chemistry 15점 vs medicine 1점).
   얇은 셀은 적응적 깊이가 부모로 올려보내므로 니치 강점 포착이 늦다.
4. 사전 주제추정 오류는 미보정(로그로 진단만).

## 4. 구현 단계
| P | 내용 |
|---|------|
| P1 | ratings.ts: Welford + 켤레 사후 + 적응적 깊이 조회 + prior 체인 |
| P2 | R1 채점 훅: wire.ts에 R1 종료 후 (타사 judge들 × 내용 축 3) 중앙값 → ratings 갱신 |
| P3 | 주제 분류(고정 도메인 taxonomy + 자유 하위 라벨) — judge 콜 동승 |
| P4 | --auto-team 톰슨 + provider≥2 + 중복금지 |
| P5 | affinity 삭제 → ratings 커맨드, CLAUDE.md BT 서술 수정, 호스트 스킬 갱신 |

## 5. 최종 검토 질문 (pyreez 심의용)
- R1 채점의 프롬프트 의존성: R1 프롬프트는 프로토콜별로 다르다(shared_convergence 렌즈 강제 등).
  같은 (model, topic) 셀에 다른 프로토콜 R1 점수를 합산해도 되나?
- judge 콜 비용: 매 실행 워커 n × judge 2 = 2n 콜 추가. 수용 가능한 기본값인가, 샘플링(예: 실행의 50%)이 나은가?
- 적응적 깊이의 신뢰 임계 n을 얼마로? (실측상 내용 축 신호 9~15점, judge 중앙값 노이즈 대비)
